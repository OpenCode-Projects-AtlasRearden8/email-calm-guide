# Email Calm Guide

A friend-style manual for taming email and inbox dread — written like a friend would explain it: plain English, step by step, for tired humans.

**What it covers:** a ten-minute daily tidy, a three-folder system, guilt-free unsubscribing, fast and kind replies (with fill-in templates), a local AI helper that drafts and shortens on your own machine, rules and auto-reply, scam-resistant habits, a weekly reset checklist, a common-mistakes page, and a digging-out rescue plan for when the inbox is already a landslide.

**Local-first, boring-by-design:** no accounts, no API keys, no telemetry, no build dependencies. Python standard library only.

## Quick start

```bash
python3 build.py          # build the static site into site/
python3 build.py --serve  # build, then preview at http://127.0.0.1:8000
python3 tests/test_all.py # run the test suite
```

Open `site/index.html` in any browser — double-clicking the file works, no server needed. The `--serve` flag is only for people who like a localhost preview; nothing is published anywhere by anything in this repo.

## What's in the box

```text
docs/                 the manual, one chapter per markdown file (00–12)
templates/replies/    fill-in reply templates (yes, kind no, checking in, ...)
assets/style.css      the site's single stylesheet
site/                 BUILT OUTPUT — the static site, regenerated by build.py
build.py              stdlib-only site builder (markdown -> HTML, no deps)
tests/test_all.py     the test suite (build, converter, content, hygiene)
STATUS.md             what was built, how it was verified, known gaps
```

## How to use it

1. **Build:** `python3 build.py` → produces `site/` (13 chapters + a template library page).
2. **Preview:** `python3 build.py --serve` → serves `site/` on `127.0.0.1:8000`, Ctrl+C to stop. The preview only serves one folder on your own machine.
3. **Test:** `python3 tests/test_all.py` → builds to a temp copy, checks pages, templates, markdown-converter behavior, internal links, LICENSE/README clauses, and scans the repo for accidental API keys.

## The system in one breath

1. Inbox = landing strip, not home. Three folders: **Needs action**, **Waiting on**, **Someday**.
2. One 10-minute tidy a day, four moves: reply under-2-minute things, move, archive, unsubscribe.
3. Replies are three sentences and a date; the templates do the shaping, you fill the yellow blanks.
4. Rules file the noise; auto-reply tells people the truth about your response time.
5. Weekly reset (15 minutes) keeps folders honest, sends up to three gentle nudges, unsubscribes from one sender, fixes one rule.
6. Optional: a small local model (Ollama or LM Studio) drafts, shortens, and summarizes — pair it with kind-email-crafter-cli, which reads the same template files.
7. And a firehose rescue plan exists for the weeks this all got away from you. It starts with a five-minute holding reply and one big archive.

## Pairs with kind-email-crafter-cli

The templates in `templates/replies/` are plain markdown files with a tiny header (name, when, tone, subject) and `__fill in__` blanks — this manual's companion tool kind-email-crafter-cli reads exactly those files and drafts replies locally, no cloud. If you don't use that tool, everything still works by copy-paste.

## Privacy posture

Everything in this repo runs 100% locally and makes no network calls at all — neither the build script nor the tests. The optional preview server only serves one folder on your own machine. There are no analytics, no fonts fetched from a CDN, and no "call home" of any kind in the built pages.
